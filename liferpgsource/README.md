# 첫 삽

미루던 일은 시작이 제일 무겁습니다.
통째로 보면 못 하니까, 첫 조각 하나만 꺼내 드립니다.

```
"밀린 세금 서류 정리해서 제출"   ← 23일 묵힘
        ↓
첫 삽 · 5분
서류 담을 폴더 하나 만들기. 그것만 하세요.

  [ 했다 ]  [ 이것도 버거워 ]  [ 오늘은 넘길래 ]
```

## 이 앱이 다른 점

**"다 했어?"가 아니라 "시작했어?"를 묻습니다.** 미루는 사람에게 진짜 장벽은
완료가 아니라 시작이니까요.

설계의 근거가 되는 방정식은 하나입니다.

```
미룬다 = 예상 고통 > 예상 보상
```

앱이 하는 일도 그래서 둘뿐입니다 — 왼쪽을 **쪼개서** 낮추고,
오른쪽을 **인정으로** 올립니다.

## 빠르게 실행하기

```bash
npm install
cp .env.example .env
npx prisma migrate dev
npm run dev               # http://localhost:3000
```

> **`ANTHROPIC_API_KEY` 가 필요합니다.** 쪼개기는 규칙 기반으로 대체할 수 없습니다 —
> "세금 서류 제출"을 의미 있는 조각으로 나누려면 그게 뭔지 이해해야 하니까요.
> 키가 없으면 임시 문구로 대체되지만, 그 상태로는 이 앱의 핵심을 확인할 수 없습니다.

## 환경변수

| 변수 | 필수 | 없으면 |
|---|---|---|
| `DATABASE_URL` | ✅ | 기본값 `file:./prisma/dev.db` |
| `ANTHROPIC_API_KEY` | ✅ | 쪼개기·인정이 임시 문구로 대체 (검증 불가) |
| `SESSION_SECRET` | 배포 시 ✅ | 개발용 고정 키 사용 (운영에서는 실행 거부) |
| `APP_TIMEZONE` | — | 기본값 `Asia/Seoul` (묵힌 일수의 "하루" 기준) |

## 설계 규칙

이 규칙들은 취향이 아니라 실패에서 나왔습니다.

- **앱은 판단하지 않는다. 사실을 보여준다.** 등급표를 만들면 "13글자라서 D급"
  같은 일이 다시 벌어집니다
- **묵힌 일수는 인정의 크기를 정하지 않는다.** 묵힐수록 크게 쳐주면
  미루기를 보상하는 앱이 됩니다. 3일이든 30일이든 온전한 인정을 줍니다
- **한 번에 3개만 보인다.** 스무 개를 늘어놓으면 목록 자체가 죄책감이 됩니다
- **불편함의 강도는 일정하다.** 숫자는 자라지만 앱의 목소리는 커지지 않습니다.
  강도가 같이 커지면 어느 순간 앱을 지웁니다
- **넘긴 날은 어디에도 기록하지 않는다.** 담을 테이블 자체가 없습니다
- **등록에 필요한 결정은 0개.** 분류·마감일·우선순위·난이도·이모지 전부 안 묻습니다
